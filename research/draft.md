# Agenci computer use: co działa i co z tego wziąć do cursor-computer-use

> Przegląd badań nad agentami sterującymi komputerem przez interfejs graficzny, z listą ulepszeń dla serwera MCP, który daje Grokowi w Cursorze dostęp do Maca.

## Percepcja: obraz czy struktura interfejsu

W benchmarku OSWorld sam zrzut ekranu dawał najsilniejszym modelom wizyjnym tylko kilka procent skuteczności, a autorzy podkreślają, że drzewo dostępności odegrało decydującą rolę [@xie2024osworld, p. 13 :: "The main experiment revealed the decisive role of the a11y tree in performance within the current technological context."]. Ten sam kierunek widać w agentach webowych: najlepsza strategia w SeeAct łączy strukturę HTML z obrazem [@zheng2024ision, abstract :: "the best grounding strategy we develop in this paper leverages both the HTML structure and visuals"]. Agent Navi osiągnął najlepszy wynik 19.5% w Windows Agent Arena dzięki połączeniu znaczników, drzewa dostępności systemu i detektorów elementów z pikseli [@bonatti2024windows, p. 2 :: "using Set-of-Marks prompting (Yang et al., 2023) combined with the system accessibility tree and pixel-based element detectors"]. Agent S używa obrazu do śledzenia zmian, a drzewa dostępności do precyzyjnego wskazywania elementów [@agashe2024agent, p. 2 :: "a dual-input strategy using visual input for understanding environmental changes together with an image-augmented accessibility tree for precise element grounding"]. UFO2 łączy Windows UI Automation z parsowaniem obrazu [@zhang2025desktop, abstract :: "A hybrid control detection pipeline fuses Windows UI Automation (UIA) with vision-based parsing to support diverse interface styles."].

Struktura ma jednak słabe strony. Autorzy UGround zwracają uwagę, że drzewa dostępności wnoszą szum, braki i dodatkowy koszt [@gou2024navigating, abstract :: "text-based representations such as HTML or accessibility trees, which, despite their utility, often introduce noise, incompleteness, and increased computational overhead"]. Przegląd metod efektywności opisuje je jako zwarte, ale często niekompletne lub niezgodne z tym, co widać na ekranie [@bai2026efficient, p. 5 :: "while DOM or AxTree representations are compact yet often incomplete, noisy, or misaligned with the rendered interface"]. Gdy struktura i obraz sobie przeczą, modele potrafią nadmiernie ufać błędnej strukturze [@zhang2026agents, p. 15 :: "The high conflict sfr (clear pixels, wrong structure) therefore reflects over-trust only when pixels are informative"].

Ogólne modele wizyjno-językowe wciąż słabo trafiają w elementy. Najlepsze strategie w SeeAct zostawały o 20-25% za idealnym wskazywaniem [@zheng2024ision, p. 8 :: "The most effective grounding strategies we explored in this paper still exhibit a 20-25% performance gap compared to oracle grounding."]. Na ekranach profesjonalnych o wysokiej rozdzielczości najlepszy model w ScreenSpot-Pro osiągnął tylko 18.9% [@li2025screenspot, abstract :: "Existing GUI grounding models perform poorly on this dataset, with the best model achieving only 18.9%."]. Pomagają znaczniki nałożone na obraz [@yang2023mark, p. 2 :: "Our experiments show that SoM can drastically unleash the grounding capability of GPT-4V."] i parsowanie zrzutu na elementy [@lu2024omniparser, p. 1 :: "OMNIPARSER significantly improves GPT-4V's performance on ScreenSpot benchmark."]. Wynik nie jest jednak jednoznaczny: w agentach webowych same znaczniki okazały się nieskuteczne [@zheng2024ision, abstract :: "Existing LMM grounding strategies like set-of-mark prompting turns out to be not effective for web agents"].

Najprostszy sposób na lepsze trafianie bez trenowania modelu to zawężenie obszaru. ScreenSpot-Pro pokazał, że ograniczenie obszaru poszukiwań poprawia dokładność [@li2025screenspot, abstract :: "Our experiments reveal that strategically reducing the search area enhances accuracy."]. W eksperymentach GUI-Lens, z kadrowaniem od ogółu do szczegółu dla modeli ogólnego przeznaczenia, wyniki były wyższe nawet o 24.9 punktu procentowego [@fu2026lens, p. 2 :: "Experiments across four grounding benchmarks and three general-purpose VLM backends show improvements of up to 24.9 percentage points"]. DRS-GUI uzyskał stałe zyski zwłaszcza na gęstych interfejsach w wysokiej rozdzielczości [@liu2026dynamic, p. 8 :: "show consistent gains over strong general and GUI-specific MLLMs, especially on high-resolution, element-dense interfaces"]. UI-Zoomer opiera się na tej samej obserwacji: przycięcie i ponowne wskazanie w wyższej rozdzielczości wiąże się z dokładniejszą lokalizacją [@tang2026zoomer, abstract :: "Test-time zoom-in methods improve localization by cropping and re-running inference at higher resolution"]. Wyższa rozdzielczość zrzutu sama w sobie zwykle pomaga [@xie2024osworld, p. 13 :: "Higher screenshot resolution typically leads to improved performance"].

## Szybkość: mniej wywołań modelu

Agenci są wolni głównie przez wywołania dużego modelu. Badanie OSWorld-Human przypisuje większość opóźnienia planowaniu, refleksji i ocenie wykonywanym przez duży model [@abhyankar2025osworld, abstract :: "We find that large model calls for planning, reflection, and judging account for most of the overall latency"]. Nawet najlepsze z 16 badanych agentów wykonywały 2.7-4.3 razy więcej kroków niż potrzeba [@abhyankar2025osworld, p. 1 :: "even the best agents take 2.7-4.3× more steps than necessary"]. Każdy krok to osobne wywołanie modelu, więc mniej kroków to mniejsze opóźnienie i koszt [@zhang2025desktop, p. 19 :: "Because each step requires an LLM call, reducing the number of steps significantly lowers both latency and cost."]. Mniej myślenia nie musi jednak przyspieszać pracy: cua-speedrun odnotował, że więcej rozumowania może skrócić czas zadania, bo agent unika powtarzania nieudanych akcji [@aggarwal2026speedrun, p. 9 :: "more reasoning can reduce task time by avoiding repeated unsuccessful actions, while faster I/O can increase it through additional interaction"].

Dwie techniki skracają liczbę kroków. Pierwsza to kilka akcji w jednym wywołaniu: w pomiarach UFO2 koszt wnioskowania był niższy nawet o 51.5% bez utraty niezawodności [@zhang2025desktop, p. 14 :: "Speculative multi-action execution consolidates multiple steps into a single LLM call, lowering inference cost by up to 51.5% without compromising reliability."]. Druga to akcje przez API lub narzędzia zamiast klikania. Według autorów UFO2 natywne API wiązały się ze skutecznością wyższą o ponad 8% i mniejszą kruchością niż samo klikanie [@zhang2025desktop, p. 14 :: "Allowing AppAgents to invoke native APIs or GUI interactions to improve completion rate by over 8%, cuts latency and reduces the fragility seen in purely click-based workflows."]. UltraCUA z akcjami hybrydowymi był o 22% skuteczniejszy względnie i o 11% szybszy [@yang2025ultracua, p. 1 :: "On OSWorld, UltraCUA achieves 22% relative improvement while executing 11% faster than existing approaches on average."]. W OSWorld-MCP narzędzia MCP podniosły skuteczność na przykład z 8.3% do 20.4% dla OpenAI o3 [@jia2025osworld, abstract :: "MCP tools generally improve task success rates (e.g., from 8.3% to 20.4% for OpenAI o3 at 15 steps"].

Narzędzia nie działają jednak same z siebie. Nawet najmocniejsze modele sięgały po nie w 36.3% przypadków [@jia2025osworld, abstract :: "even the strongest models have relatively low tool invocation rates, Only 36.3%"]. W tej samej konfiguracji wynik modelu rozumującego wzrósł o +4.0pp, a modelu bez rozumowania spadł o -5.9pp [@fan2026screenshots, abstract :: "the same MCP tools improve a reasoning model by +4.0pp and degrade a non-reasoning model by -5.9pp"]. ToolCUA opisuje niepewność agentów co do tego, kiedy klikać, a kiedy użyć narzędzia [@hu2026toolcua, abstract :: "this hybrid action space often leaves them uncertain about when to continue with GUI actions or switch to tools, leading to suboptimal execution paths"].

Największe oszczędności przy powtarzalnych zadaniach daje ponowne użycie udanych przebiegów. W eksperymentach EchoPath, który odtwarza zweryfikowane sekwencje akcji, mediana kosztu tokenów była niższa o ponad 90%, a mediana czasu o około 60% [@zhao2026echopath, abstract :: "EchoPath reduced median token cost by more than 90% and median execution time by about 60%."]. Pamięć przepływów AWM dała względny wzrost skuteczności o 24.6% i 51.1% [@wang2024agent, p. 11 :: "We evaluate AWM on WebArena and Mind2Web, and achieve 24.6% and 51.1% relative increases in task"]. Polityki neuro-symboliczne wiązały się z większą niezawodnością powtarzanych zadań oraz niższym kosztem i opóźnieniem każdego przebiegu [@suh2026neuro, p. 11 :: "the resulting policies improve reliability under repeated execution while substantially reducing per-run cost and latency"]. Odtwarzanie wymaga jednak zabezpieczeń: EchoPath odrzuca niejednoznaczne kroki i wraca do naprawy wskazań albo do planowania od nowa [@zhao2026echopath, abstract :: "rejects ambiguous or incompatible steps to bounded grounding repair or fresh planning"].

## Niezawodność i macOS

Na macOS agenci wciąż często zawodzą. W macOSWorld najlepsze systemy komercyjne przekraczały 30% skuteczności [@yang2025macosworld, abstract :: "proprietary computer-use agents lead at above 30% success rate"], a w MacArena najlepszy wynik wyniósł 31.83% [@muryn2026macarena, p. 6 :: "OpenAI Computer Use Preview achieves the highest overall success rate of 31.83%"]. Analiza błędów GUITAR pokazuje, że większość pomyłek to nieukończenie zadania, błędne postrzeganie stanu, złe zrozumienie instrukcji i brak wiedzy o interakcji [@zhang2026guitar, p. 20 :: "Task Completion Failures (TCF), State Perception Failures (SPF), Instruction Grounding Failures (IGF), and Interaction Knowledge Failures (IKF) account for the majority of errors"]. Według przytaczanych danych 56.7% akcji agentów trafia w zły element [@liu2026visual, p. 2 :: "56.7% of CUA actions target the wrong element"], a stan ekranu może się zmienić między zrzutem a kliknięciem [@liu2026visual, p. 3 :: "The screen state can change between screenshot() and click()"].

## Bezpieczeństwo

Treści widoczne na ekranie łatwo przejmują agentów. Spreparowane pop-upy skłaniały je do kliknięcia w 86% przypadków, a skuteczność zadań była wtedy niższa o 47% [@zhang2024attacking, abstract :: "leads to an attack success rate (the frequency of the agent clicking the pop-ups) of 86% on average and decreases the task success rate by 47%"]. Proste obrony, takie jak polecenie ignorowania pop-upów, nie działały [@zhang2024attacking, abstract :: "Basic defense techniques, such as asking the agent to ignore pop-ups or including an advertisement notice, are ineffective against the attack."]. W OS-Harm wszystkie modele często wykonywały polecenia nadużycia i były podatne na wstrzyknięte polecenia [@kuntz2025harm, abstract :: "all models tend to directly comply with many deliberate misuse queries, are relatively vulnerable to static prompt injections, and occasionally perform unsafe actions"]. Ataki rozłożone na kilka kroków zachowują skuteczność lepiej niż jednokrokowe [@zhan2026stepjack, p. 8 :: "multi-step attacks retain more of their effectiveness under both defenses than single-step attacks do"]. Autorzy macOSWorld piszą, że ataki przez zwodzenie są ogólne i wymagają pilnej uwagi [@yang2025macosworld, abstract :: "deception attacks are more general and demand immediate attention"], a systematyzacja podatności wskazuje, że wiele zagrożeń wynika z architektury, nie tylko z zachowania modelu [@jones2025systematization, p. 1 :: "many of these risks are architectural, not just behavioral, and persist across agents, frameworks, and guardrail implementations"].

Najmocniejsze gwarancje daje izolacja architektoniczna, czyli oddzielenie zaufanego planu zadania od niezaufanych obserwacji [@foerster2026camels, abstract :: "architectural isolation provides the strongest guarantees by strictly separating trusted task planning from untrusted environment observations"]. Praktyczny wariant to strażnik działający poza agentem, który sprawdza każde kliknięcie razem ze zrzutem [@liu2026visual, p. 4 :: "The guardrail operates outside the agent process: it intercepts each click(x,y) together with the screenshot and the LLM's reasoning text."]. Ograniczenie jest takie, że agent musi stale obserwować ekran, co kłóci się z pełną izolacją [@foerster2026camels, abstract :: "Current agents require continuous observation of UI state to determine each action, which conflicts with the isolation required for security."]. Szkoda może też powstać przy całkiem niewinnym poleceniu użytkownika [@ding2026blind, abstract :: "where user instructions are entirely benign and harm arises from the task context or execution outcome"].

## Wnioski

Nasz serwer już stosuje to, co badania wskazują jako najskuteczniejsze: hybrydę drzewa dostępności z obrazem i OCR, akcje po etykiecie zamiast celowania w piksele, łączenie kroków w batch oraz deep linki zamiast klikania. Kolejne ulepszenia według spodziewanego zysku:

1. **Przepisy, czyli zapamiętane przebiegi.** Po udanym zadaniu zapisać sekwencję akcji semantycznych (click_text, fill, menu, open_url) z punktami kontrolnymi wait_for. Przy powtórce odtworzyć ją jednym wywołaniem, a przy pierwszej niezgodności oddać sterowanie modelowi. To ulepszenie z najmocniejszym efektem w badaniach dla zadań powtarzalnych [@zhao2026echopath, abstract :: "EchoPath reduced median token cost by more than 90% and median execution time by about 60%."].
2. **Sprawdzanie celu przed kliknięciem.** Przy click(x, y) odczytać przez Accessibility element pod punktem i zgłosić, w co kliknięcie trafi lub trafiło. Chroni to przed pomyłkami i przed zmianą ekranu między zrzutem a kliknięciem [@liu2026visual, p. 3 :: "The screen state can change between screenshot() and click()"].
3. **Potwierdzenie poza modelem dla ryzykownych akcji.** Kliknięcia w elementy typu Wyślij, Kup, Usuń, Zapłać zatrzymuje serwer, a nie model, i pyta użytkownika natywnym oknem. Zgodnie z badaniami same instrukcje dla modelu nie wystarczają [@zhang2024attacking, abstract :: "Basic defense techniques, such as asking the agent to ignore pop-ups or including an advertisement notice, are ineffective against the attack."].
4. **Zoom do klikania.** Zoom ma zwracać fragment z siatką opisaną we współrzędnych pełnego zrzutu, żeby model mógł kliknąć dokładnie w to, co widzi w powiększeniu (podejście od ogółu do szczegółu) [@li2025screenspot, abstract :: "Our experiments reveal that strategically reducing the search area enhances accuracy."].
5. **Narzędzia aplikacji zamiast klikania.** Dla aplikacji skryptowalnych (Muzyka, Notatki, Przypomnienia, Safari, Finder) dodać gotowe akcje przez AppleScript, a w skillu jasno opisać, kiedy po nie sięgać, bo modele same rzadko korzystają z narzędzi [@jia2025osworld, abstract :: "even the strongest models have relatively low tool invocation rates, Only 36.3%"].
6. **Zostawić Groka w trybie rozumowania.** Narzędzia pomagają modelom rozumującym, a szkodzą tym bez rozumowania, a więcej myślenia może skrócić całe zadanie [@fan2026screenshots, abstract :: "the same MCP tools improve a reasoning model by +4.0pp and degrade a non-reasoning model by -5.9pp"]. To odwraca wcześniejszą sugestię, żeby obniżyć poziom myślenia.
